# Controlled course-task adapters

The five public fixture sets and private deterministic validators are implemented and frozen for the completed 50-trial full/compact comparison. They contain the same case data selected for the authentic NanoAgent pilots, with the explicit information-access changes below. All five source checkouts were clean at the manifest's pinned commits during extraction; every source manifest is version `0.1.0`. The final experiment identity is in `study/controlled/final/freeze.json`; fixture preparation itself is not a model result.

## Public inputs and provenance

[fixtures/manifest.json](../study/controlled/fixtures/manifest.json) records each case ID, task, source repository/commit/version, source-file SHA-256 hashes, exact public file hashes and sizes, output schema, extraction recipe, generator digest and license. Each case directory contains **only `input.json` and `prompt.txt`**. Copy only those two files into a fresh evaluated workspace. Do not mount the whole project.

| Fixture directory / case ID | Public `input.json` fields | Input bytes | Adaptation |
| --- | --- | ---: | --- |
| `log-triage/edge-proxy` | `case`, eight ordered `lines` | 727 | Original public log now read from a file. |
| `cipher-crack/telegram` | `case`, `ciphertext` | 85 | Candidate shifts can be computed using generic tools instead of `decrypt`. |
| `path-probe/quarry` | `case`, `start`, `goal`, seven `links` | 541 | **Full graph** replaces the original partial-neighbour discovery interface. |
| `regex-infer/widget-code` | `case`, thirteen visible labelled `examples` | 832 | Generic local testing replaces the public `try_pattern` tool. |
| `stat-pick/sensor-drift` | `case`, `column`, verbatim `question`, eleven `numbers` | 316 | **Raw readings** replace the original summary-only interface. |

These are UTF-8 file byte counts, not tokens. JSON is rendered with two-space indentation and a final newline. Prompt files have no leading or trailing whitespace, as benchmark publication requires; their internal newlines are preserved. Ciphertext is derived from the selected source literal through independent Caesar arithmetic, but the plaintext and key are never written to the public fixture. The regex exporter selects only `VISIBLE`; it does not export the rule or holdouts. Log labels/evidence annotations, expected routes/costs and the statistics choice/value remain private. Prompts define each task and its output schema without a worked answer or a required tool strategy.

Both experimental conditions use identical fixture bytes and exact prompt text. Output-formatting treatment belongs in the shared CLI; it must not rewrite case prompts or fixtures. These prompts intentionally differ from the original Session case-only requests. Report the custom comparisons as adapted tasks, especially graph and statistics, and retain the original pilots separately.

The [AST exporter](../study/controlled/validators/build_fixtures.py) uses an explicit per-task field allowlist and `ast.literal_eval`; it never imports or executes plugin code. It refuses an unpinned or dirty checkout. The shared [upstream MIT notice](../study/controlled/fixtures/LICENSE.upstream-MIT.txt), copyright 2026 Yifei Wang, is preserved unchanged. Keep it with distributed source-derived fixtures and project releases. The manifest identifies the same notice and its hash for all five sources.

Reproduce the generated bytes from the pinned local source checkouts:

```sh
python3 study/controlled/validators/build_fixtures.py
```

The command deterministically regenerates public files, their manifest, and `validators/references.json`. It makes no network/model requests. Do not regenerate after freezing an experiment without recording the new artifact versions. The tests rebuild into a temporary directory and compare every generated byte.

## Private evaluation interface

The researcher-side API is [validate.py](../study/controlled/validators/validate.py):

```python
result = validate_case("path-probe/quarry", workspace)
```

Its CLI runs after the agent has stopped:

```sh
python3 study/controlled/validators/validate.py \
  --case path-probe/quarry --workspace /absolute/path/to/completed/workspace
```

Exit `0` means the local checks passed, `1` means a task/schema/integrity failure, and `2` means a verifier/setup error with unknown success. The JSON result keeps `integrity`, `answer_schema` and `task_verdict` separate. `valid` is the overall local outcome; `task_verdict.valid` is semantic correctness and `task_verdict.score` is the upstream-style partial score. For example, an answer can be semantically correct while overall `valid` is false because the input changed. A schema failure has no task verdict. These are local checks, not forged RUSH verdicts; retain the platform's actual result alongside them when a scored benchmark runs.

The checker requires regular nonsymlink `input.json`, `prompt.txt` and `answer.json`. Both public input files must retain the manifest's exact bytes. Answer JSON must have exactly the declared fields and types, the selected case and valid enums; duplicate keys, nonfinite numbers, booleans in numeric fields and malformed JSON are rejected. `cost` is an integer; a statistic value must be a finite representable number. There is a documented 64-KiB local answer-file ceiling. These host integrity/encoding checks are reported separately from task semantics.

| Task | Reproduced semantic acceptance |
| --- | --- |
| Log | Fault enum exact; evidence stripped only at its outer boundary. Any pinned accepted diagnostic line passes. Wrong fault scores 0, invented evidence 0.25, existing nondiagnostic evidence 0.5. Label/citation agreement does not independently prove causality. |
| Cipher | Key and plaintext receive upstream strip/uppercase normalization. Key must be one A–Z letter; normalized plaintext is nonblank, at most 400 characters and contains only A–Z/spaces. Independently decrypt and compare both submitted and expected plaintext. Wrong key plus correct text can have score 1 while `valid=false`. |
| Path | Existing undirected edges, exact endpoints, no repeated nodes, at most 100 nodes and exact summed integer cost. Exhaustive simple-path enumeration on the fixed six-node graph independently establishes optimality. Both optimal alternatives pass; a valid dearer route scores optimum/submitted cost. |
| Regex | Nonblank pattern, no surrounding whitespace, at most 120 characters, valid Python syntax and the pinned lexical nested-quantifier restriction. Grade only the ten held-out examples using `re.fullmatch`; success establishes finite-set agreement, not language equivalence. Actual matching runs in a private subprocess with a two-second operational timeout; a timeout is a verifier error, not a wrong answer. |
| Statistics | Expected statistic label exact; recompute population deviation using independent explicit arithmetic. Numerical tolerance is `1e-6 * max(1, abs(expected))`. Wrong statistic scores 0; right statistic with wrong value scores 0.5. |

The private [references.json](../study/controlled/validators/references.json), validator code, regex worker, tests and source checkouts must remain outside the evaluated VM and CLI package. A separate host directory is insufficient if the agent has unrestricted host Python access. For scored runs also pin `internet_access: false`: upstream public repositories contain solution data, so merely removing local files does not close the reference boundary. No hidden verifier output is given back to the agent during final trials.

## Verification and current limits

Run the independent synthetic checks with:

```sh
python3 -m unittest discover -s study/controlled/tests -p 'test_validators.py' -v
```

All 23 tests pass. They cover all five correct answers, both optimal routes and accepted citations, cipher normalization and false-score-1 behavior, wrong choices/values, internal spacing, malformed schemas, booleans, huge integers, duplicate keys, NaN/overflow, input/prompt mutations or absence, symlinks, regex memorization, finite-set scope and timeout handling. They also check public allowlists, hidden-value exclusions, source-derived file/license hashes and byte-identical regeneration. These are offline tests with synthetic submitted answers, not model-backed task attempts.

No source plugin code was executed to create fixtures or run these tests. The local validators reproduce the audited selected-case semantics. Native scored Log Triage smoke subsequently passed; all five published cases were exercised by the completed frozen final study. Native and local verdicts remain separately reported. The full-loop CLI and benchmark workflow are separate components. See [HARNESS_CONTRACT.md](../docs/HARNESS_CONTRACT.md) for that interface, the recorded platform compatibility fix and the fixed-model limitation. The [development record](../study/controlled/validators/DEVELOPMENT.md) preserves the implementation request and validation rationale.
